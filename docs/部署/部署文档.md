# BLACK ERP 部署文档

> 适用版本：v1.0（S1–S5）
> 部署形态：**内网 Windows 服务器 + frp 内网穿透**（远程可选）；Docker Compose 为推荐方式，同时提供无 Docker 的原生 Windows 部署路径。
> 关联文档：[架构设计/部署架构](../架构设计/架构设计文档.md) · [开发设计/后端](../开发设计/后端开发文档.md)

## 1. 部署拓扑

```
用户浏览器(内网PC)
      │  http://<服务器内网IP>
      ▼
┌─────────────────────────────────────────────┐
│  Windows 服务器（内网）                       │
│  ┌─────────┐                                 │
│  │  nginx  │ :80  ← 前端静态 + /api 反代      │
│  └────┬────┘                                 │
│       ├─→ app(FastAPI/uvicorn)  :8000         │
│       │        ├─→ MySQL 8    :3306          │
│       │        └─→ Redis 7    :6379          │
│       ├─→ worker(Celery)  计算/报表/提醒      │
│       └─→ beat(Celery)    定时任务           │
│                                             │
│  frpc ──TCP──→ 公网 frps :7000 ──→ :18080    │
└─────────────────────────────────────────────┘
      远程用户：http://<公网IP>:18080（可选）
```

| 组件 | 端口 | 说明 |
|---|---|---|
| nginx | 80 | 唯一对外入口（前端 + API 反代） |
| app | 8000 | FastAPI，仅本机/nginx 内网访问 |
| MySQL | 3306 | 生产建议仅容器网络/本机访问 |
| Redis | 6379 | 会话 + Celery broker，仅内网 |
| frps（远端） | 7000 / 18080 | 隧道控制端 / 对外映射端 |

## 2. 环境要求

| 项 | 要求 |
|---|---|
| 操作系统 | Windows Server 2016+ / Windows 10+（内网服务器） |
| Docker | Docker Desktop 4.x+（含 Compose v2）——**推荐** |
| 无 Docker 时 | Python 3.12+、Node 18+、MySQL 8.0、Redis（Windows 版） |
| 资源 | ≥4C / ≥8GB 内存 / ≥50GB 磁盘（订单 CSV 与上传件会增长） |
| 网络 | 内网互通；远程访问需一台公网服务器跑 frps |
| 浏览器 | Chrome / Edge 最新版（首期仅支持 PC） |

## 3. 部署前准备

### 3.1 获取代码

将项目目录整体拷贝（或 git clone）到服务器，例如 `D:\black_erp`。目录结构应包含：

```
black_erp/
├── backend/                 # FastAPI 后端（含 Dockerfile）
├── frontend/                # Vue3 前端源码
├── deploy/
│   ├── scripts/             # ★ 编号部署/运维 bat 脚本
│   ├── nginx.conf
│   ├── frpc.toml.example
│   └── frps.toml.example
├── docker-compose.yml
├── .env.example
└── docs/
```

### 3.2 防火墙

仅开放：`80`（内网）、`7000`+`18080`（仅 frps 公网机需要）。`3306/6379/8000` **不对内网全段开放**，按需限制来源 IP。

### 3.3 远程访问（可选，先记后配）

内网直接用即可跳过。需要远程时按 §7 配置 frp。

## 4. 部署脚本总览（主路径）

所有脚本位于 `deploy\scripts\`，在**项目根目录**用 cmd/双击执行（自动 `cd` 到根目录）。编号即执行顺序，均已幂等——失败修复后可单独重跑。

| 顺序 | 脚本 | 作用 |
|---|---|---|
| ★ | `00_deploy_all.bat` | 一键顺序执行 01→06（推荐） |
| 1 | `01_check_env.bat` | 检查 Docker / Node18+ / 端口80 / .env |
| 2 | `02_init_env.bat` | 生成 `.env`（随机 SECRET_KEY，已存在则跳过） |
| 3 | `03_build_frontend.bat` | `npm install` + `build` 产出 `frontend/dist` |
| 4 | `04_init_db.bat` | 启动 MySQL/Redis → 等就绪 → `python -m app.init_db` 建表+种子 |
| 5 | `05_start.bat` | `docker compose up -d --build` 启动全部服务 |
| 6 | `06_verify.bat` | 健康检查 /health + 登录页 200 + 容器状态 |
| 运维 | `10_backup.bat` | mysqldump + 上传件打包 + 配置 → `backup\<时间戳>\` |
| 运维 | `11_start.bat` / `12_stop.bat` | 启动 / 停止（数据卷保留） |
| 运维 | `13_logs.bat` | 跟随 app/worker/beat 日志（Ctrl+C 退出） |

## 5. Docker Compose 部署步骤（按脚本顺序）

### 5.1 一键部署

```bat
rem 双击或在 cmd 中：
deploy\scripts\00_deploy_all.bat
```

脚本会依次跑 01→06，中途在生成 `.env` 后**暂停一次**，提示编辑 `.env` 改生产密码，回车继续。

### 5.2 分步执行（等价于一键）

```bat
deploy\scripts\01_check_env.bat
deploy\scripts\02_init_env.bat
rem >>> 此时编辑根目录 .env，必改：SECRET_KEY(已随机)、MYSQL_ROOT_PASSWORD、MYSQL_PASSWORD、APP_ENV=prod
deploy\scripts\03_build_frontend.bat
deploy\scripts\04_init_db.bat
deploy\scripts\05_start.bat
deploy\scripts\06_verify.bat
```

> ⚠️ 数据库密码必须在**首次** `04_init_db.bat`（MySQL 容器初始化）之前改好；之后再改 `.env` 不会自动改已初始化的 MySQL 密码。

### 5.3 `.env` 生产必改项

| 变量 | 生产值 | 说明 |
|---|---|---|
| `SECRET_KEY` | 02 脚本已随机生成 | Session 签名密钥，勿再变动 |
| `APP_ENV` | `prod` | 关闭自动建表/seed、关闭 /api/docs |
| `MYSQL_ROOT_PASSWORD` | 强密码 | MySQL root，**首次建库前**改 |
| `MYSQL_PASSWORD` | 强密码 | 业务账号 erp，**首次建库前**改 |
| `SECURE_COOKIE` | `true`（走 HTTPS 时） | 内网纯 HTTP 保持 `false` |
| `MAX_UPLOAD_MB` | 保持 50 或按需 | 须 ≤ nginx `client_max_body_size` |

> ⚠️ `.env` 含全部密码，禁止提交 git（已在 .gitignore），只在服务器留存。

### 5.4 部署验证清单（06 脚本 + 人工抽验）

脚本自动检查：`/health` 返回 `{"ok":true}`、登录页 HTTP 200、容器 running/healthy。

人工再抽验业务链路（内网浏览器）：

1. `http://<服务器IP>/` → 登录页正常渲染，admin 登录成功
2. 「成本报价 → 规格成本表」新增一条规格（写库正常）
3. 「财务核算 → 订单上传」传一份测试 CSV → 批次状态变 `success`（worker 正常）
4. 「系统管理 → 操作日志」能看到上述操作记录（审计正常）
5. admin 登录后立即在「账号管理」重置默认密码

## 6. 原生 Windows 部署（无 Docker，备选）

适合无法安装 Docker 的内网机；暂无 bat 脚本，按命令手工执行。

### 6.1 MySQL 8.0

1. 安装 MySQL 8.0（utf8mb4）。
2. 建库建号：

```sql
CREATE DATABASE black_erp CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'erp'@'localhost' IDENTIFIED BY '<强密码>';
GRANT ALL PRIVILEGES ON black_erp.* TO 'erp'@'localhost';
FLUSH PRIVILEGES;
```

### 6.2 Redis for Windows

安装 Redis（如 [tporadowski/redis](https://github.com/tporadowski/redis) 或 Memurai），默认 `6379`，注册为 Windows 服务并自启。

### 6.3 后端

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

# .env 中 DATABASE_URL/REDIS_URL 指向 127.0.0.1
python -m app.init_db                       # 建表 + seed（幂等）

# API 服务（注册为 Windows 服务或计划任务守护，示例用 nssm）：
nssm install BlackErpApp ".venv\Scripts\python.exe" "-m uvicorn app.main:app --host 127.0.0.1 --port 8000"
nssm start BlackErpApp

# Celery worker：
nssm install BlackErpWorker ".venv\Scripts\python.exe" "-m celery -A app.tasks.celery_app worker -Q celery -c 2 -Ofair -l info"
nssm start BlackErpWorker

# Celery beat：
nssm install BlackErpBeat ".venv\Scripts\python.exe" "-m celery -A app.tasks.celery_app beat -l info"
nssm start BlackErpBeat
```

> 无 nssm 时可用 `schtasks /create ... /SC ONSTART` 方案，原理相同。

### 6.4 前端 + nginx

1. `npm run build` 产出 `frontend/dist`。
2. Windows 版 nginx：把 `deploy/nginx.conf` 中 `proxy_pass http://app:8000` 改为 `http://127.0.0.1:8000`，`root` 改为 `frontend/dist` 绝对路径（正斜杠）。
3. 启动 nginx 并设为服务/自启。

验证清单同 §5.4。

## 7. frp 内网穿透（远程访问，可选）

服务器无公网 IP 时，用一台公网机做 frps，内网机跑 frpc。配置样例见 `deploy/frpc.toml.example` / `deploy/frps.toml.example`。

### 7.1 公网机（frps）

```bash
# 编辑 frps.toml：设置 bindPort=7000 与强 token
./frps -c frps.toml
```

公网防火墙放行 `7000`（隧道）与 `18080`（业务）。

### 7.2 内网机（frpc）

```powershell
# 编辑 frpc.toml：serverAddr=公网机IP，token 与 frps 一致
.\frpc.exe -c frpc.toml
```

同样注册为 Windows 服务自启：

```powershell
nssm install BlackErpFrpc "C:\frp\frpc.exe" "-c C:\frp\frpc.toml"
nssm start BlackErpFrpc
```

### 7.3 访问与安全

- 远程用户访问 `http://<公网IP>:18080`。
- **强烈建议**在公网机 frps 前再加一层 Caddy/Nginx + Let's Encrypt 做 HTTPS，并把 `.env` 的 `SECURE_COOKIE=true`。
- token 使用强随机值；限制 frps 端口白名单（仅公司出口 IP）。
- 首期内网使用可不启用 frp。

## 8. 日常运维

### 8.1 启停

```bat
deploy\scripts\11_start.bat     :: docker compose start
deploy\scripts\12_stop.bat      :: docker compose stop（数据保留）
```

```powershell
docker compose down             # 停并移除容器（named volume 数据保留）
docker compose down -v          # ⚠️ 连数据卷一起删，仅重建环境时用
```

### 8.2 升级发布

```powershell
# 1) 备份（见 8.3）
deploy\scripts\10_backup.bat
# 2) 覆盖代码
# 3) 前端产物 + 后端镜像重建（有迁移则执行）
deploy\scripts\03_build_frontend.bat
docker compose up -d --build app worker beat
# 4) 验证 §5.4 清单
deploy\scripts\06_verify.bat
```

无 Docker 时：停三个 nssm 服务 → 覆盖代码 → `pip install -r requirements.txt` → `python -m app.init_db`（幂等）→ 起新版本 → 验证。

### 8.3 备份与恢复

```bat
deploy\scripts\10_backup.bat
```

产出 `backup\<时间戳>\`：`black_erp.sql`（全库 dump）、`uploads.tgz`（上传件）、`.env` 与 `docker-compose.yml`。建议用 Windows 计划任务每日跑一次（任务指向该 bat）。

**恢复：**

```powershell
docker compose exec -T mysql mysql -uroot -p<ROOT_PW> black_erp < backup\xxx\black_erp.sql
```

保留策略建议：SQL 保留 30 天、上传件同步到 NAS/另一块盘。

### 8.4 日志

```bat
deploy\scripts\13_logs.bat
```

应用日志含 trace_id（响应头 `X-Trace-Id`），排查时用它串起一次请求。

### 8.5 定时任务（beat 内置）

| 任务 | 时间 | 作用 |
|---|---|---|
| generate_daily_report | 每日 09:00 | 聚合前一日批次 → 经营日报 |
| scan_invoice_reminders | 每小时 | 发票登记满 8 天未回传 → 站内提醒 |
| cleanup_exports | 每日 03:00 | 清理导出临时文件 |

## 9. 故障排查

| 现象 | 排查 |
|---|---|
| 登录页能开但登录 500 | `docker compose logs app`；确认 MySQL/Redis healthy、`.env` 密码正确 |
| 登录 401 反复跳登录 | `SECRET_KEY` 变更导致旧会话失效，属正常；确认时间同步（Session TTL 12h） |
| 上传后批次一直 pending | `docker compose logs worker`；worker 是否起来、broker 是否指向同一 Redis |
| 计算结果成本全 0 | 规格成本表无价格 / 匹配全 none——先「产品登记」或人工指定编码 |
| 前端 404 刷新丢失 | nginx `try_files ... /index.html` 未生效，核对 `deploy/nginx.conf` |
| 上传 413 | nginx `client_max_body_size` < 文件大小，或 > `MAX_UPLOAD_MB` |
| frp 连不上 | 公网机 7000 端口/防火墙、frpc token 与 frps 一致性、frp 两端版本一致 |
| 中文乱码（MySQL） | 确认建库 utf8mb4、compose command 带 `--character-set-server=utf8mb4` |
| bat 一闪而过 | 从 cmd 运行看报错，或直接跑对应编号脚本（结束有 pause） |
| 04 一直等 MySQL | `docker compose logs mysql`；首次初始化慢属正常，超 2 分钟报错则查密码/磁盘 |

**健康检查速查：**

```powershell
Invoke-WebRequest http://127.0.0.1/health            # 经 nginx
Invoke-WebRequest http://127.0.0.1:8000/health       # 直连 app
docker compose ps                                     # 容器状态
docker compose exec redis redis-cli ping              # PONG
```

## 10. 上线安全 Checklist

- [ ] `.env` 全部密码/SECRET_KEY 已换强随机值，`.env` 未进 git
- [ ] admin / 其他种子账号密码已全部重置
- [ ] 3306 / 6379 / 8000 未对办公网全段开放
- [ ] frp token 强随机；公网机仅开放 7000/18080（或已套 HTTPS）
- [ ] 生产 `APP_ENV=prod`（/api/docs 已关闭、自动建表已关闭）
- [ ] `10_backup.bat` 已配置计划任务并做过一次恢复演练
- [ ] 服务器 NTP 时间同步正常
