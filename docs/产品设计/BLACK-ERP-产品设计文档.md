## 1. 产品总体链路设计

### 1.1 业务全景链路

系统围绕一条主线：**"货的成本从哪来 → 卖到哪 → 这一单赚多少"**。五个岗位在同一数据链路上各司其职：

```
┌─────────┐   供应商报价    ┌─────────┐   产品登记     ┌─────────┐
│  客服    │───────────────→│  采购    │──────────────→│  运营    │
│ 售后/发票 │  供应商信息     │ 成本+编码 │  （选编码）    │ 售价/链接 │
└─────────┘                 └────┬────┘               └────┬────┘
                                 │ 规格编码（全系统主键）      │
                                 └──────────┬───────────────┘
                                            ↓
                                    ┌─────────────┐   上传订单 CSV
                                    │    财务      │←────────────── 抖店后台导出
                                    │ 匹配→计算→汇总 │
                                    └──────┬──────┘
                                           ↓
                              ┌────────────────────────┐
                              │ 老板/管理员：经营驾驶舱   │
                              │ 日报·月度对账·利润总览    │
                              └────────────────────────┘
```

### 1.2 数据流转四段式

| 阶段 | 动作 | 产出 | 责任岗位 |
|------|------|------|----------|
| ① 建主数据 | 采购录供应商报价，系统生成**规格编码**；客服维护供应商对接信息 | 成本表（编码级） | 采购/客服 |
| ② 绑店铺 | 运营按店铺登记商品：标题关键字 + **必选编码** + 规格售价 + 链接 ID | 店铺产品登记表 | 运营 |
| ③ 算成本 | 财务上传订单 CSV → 系统按"标题+售价"反查编码 → 自动算成本/利润 | 成本明细 + 汇总 + 未匹配清单 | 财务 |
| ④ 看结果 | 日报自动推送；月度对账表沉淀；驾驶舱全局查看 | 经营报表 | 老板/全员 |

### 1.3 关键设计决策（继承需求文档）

| 决策 | 结论 | 对设计的影响 |
|------|------|--------------|
| 主键 | **规格编码**为全系统主键 | 编码选择器贯穿运营登记、人工匹配、明细归集 |
| 订单匹配 | 标题关键字+规格售价反查 → 落编码 | 财务侧必须有"未匹配/人工匹配"闭环页面 |
| 地区附加 | 按件计：海南/青海/内蒙/宁夏/甘肃 +4，新疆/西藏 +20 | 附加值不进成本表，计算时按省实时叠加（规则可配置） |
| 售后 | 退货仍计成本；售后单数仅展示 | 汇总页无"成本扣回"逻辑 |
| 实收 | Σ商家收入金额，系统自动算 | 汇总页为"计算结果页"而非表单 |
| 成本表导入 | 固定模板 XLSX | 上传页只做表头校验，不做列映射向导 |

### 1.4 两条核心使用链路

**链路 A：日常成本核算（高频，财务）**

```
导出订单 CSV → 上传（识别店铺名） → 预检报告（行数/无物流数/疑似未匹配数）
→ 确认计算 → 查看汇总/明细 → 处理未匹配清单（人工指定编码） → 重算该批 → 导出
```

**链路 B：主数据维护（低频，采购/运营）**

```
采购：供应商管理 → 报价录入（手输/OCR） → 生成规格编码
运营：成本表选编码 → 登记店铺/标题/售价/链接ID
```

**设计原则**：链路 A 是价值核心，所有设计优先保证它"3 步内出结果"（上传→确认→看汇总）；链路 B 保证编码不重、录入不烦。

## 2. 信息架构

### 2.1 菜单结构（按角色裁剪）

```
工作台（待办/提醒/快捷入口）          ← 全员
├── 客服工作台                        ← 客服
│   ├── 售后登记
│   ├── 供应商对接
│   └── 发票管理（登记/回传/提醒）
├── 成本报价（采购模块）               ← 采购（写）｜运营/财务/老板（读）
│   ├── 供应商管理
│   ├── 报价录入（含 OCR）
│   ├── 规格成本表（主数据）
│   └── XLSX 模板导入
├── 运营管理                          ← 运营
│   ├── 店铺产品登记
│   └── ROI 计算
├── 财务核算                          ← 财务（写）｜老板（读）
│   ├── 订单上传与计算
│   ├── 计算批次列表
│   ├── 未匹配处理
│   ├── 成本明细 / 月度对账
│   └── 经营日报
├── 经营驾驶舱                        ← 老板/管理员
│   ├── 利润总览（多店铺）
│   ├── 日报中心
│   └── 趋势分析
└── 系统管理                          ← 管理员
    ├── 账号管理
    ├── 角色与权限
    ├── 附加成本规则（省份+金额）
    └── 操作日志
```

### 2.2 角色-页面矩阵

| 页面 | 老板 | 管理员 | 客服 | 采购 | 运营 | 财务 |
|------|:----:|:------:|:----:|:----:|:----:|:----:|
| 工作台 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 售后/发票 | – | ✓ | **写** | – | – | – |
| 供应商管理 | ✓ | ✓ | 写 | **写** | 读 | – |
| 规格成本表 | 读 | ✓ | – | **写** | 读 | 读 |
| 报价录入/OCR | – | ✓ | – | **写** | – | – |
| XLSX 导入 | – | ✓ | – | **写** | – | – |
| 店铺产品登记 | 读 | ✓ | – | – | **写** | – |
| ROI 计算 | – | ✓ | – | – | **写** | – |
| 订单上传与计算 | 读 | ✓ | – | – | – | **写** |
| 未匹配处理 | – | ✓ | – | – | – | **写** |

### 2.3 全局导航要素

- **顶栏**：消息中心、当前账号
- **工作台待办卡**：发票提醒（8 天周期）、未匹配订单数、报价待补录、日报未读
- **编码搜索（全局）**：任何页面 Ctrl+K 可按规格编码/产品名直达成本表详情

## 3. 数据模型

### 3.1 ER 总览

```
供应商 1 ──── n 规格(Spec) 1 ──── n 成本报价(历史)
                    │ 1
                    │
                    ├──── n 店铺产品登记(ShopProduct) ── n 店铺(Shop)
                    │              │
                    │              └─（标题+售价 用于订单反查）
                    │ 1
                    ├──── n 匹配规则沉淀(MatchRule)
                    │
订单(Order, 按批次导入) n ──1 计算批次(Batch)
      │ n                          │
      └──── n 订单行(OrderLine) ───┘
                │ n
                └── 1 规格(Spec)   ← 匹配成功后回填 spec_id

发票 / 售后记录 / 提醒记录 / 操作日志（独立挂账号与供应商）
```

### 3.2 核心实体定义

**Shop 店铺**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | PK | |
| name | 唯一 | 如"誉恒"；首版由 CSV 文件名前 2 字自动注册，管理员可改全名 |
| full_name / remark | 文本 | |

**Supplier 供应商**

| 字段 | 类型 | 说明 |
|------|------|------|
| id / name | PK / 文本 | |
| wechat_group | 文本 | 对接微信群 |
| contact_name / contact_phone | 文本 | |
| products | 文本 | 供应产品描述 |

**Spec 规格（全系统主键载体）** ⭐

| 字段 | 类型 | 说明 |
|------|------|------|
| id | PK | |
| spec_code | **唯一** | **规格编码**，系统自动生成：`SP + 6位序列`（如 SP000123），采购不可改 |
| product_name | 文本 | 产品名称 |
| spec_name | 文本 | 规格名（如"60g×10枚"） |
| supplier_id | FK | 默认供应商 |
| image | 附件 | 产品图片 |
| status | 枚举 | 启用/停用（停用后不可被新登记选择） |

**CostPrice 成本报价（Spec 价格历史）**

| 字段 | 类型 | 说明 |
|------|------|------|
| id / spec_id | PK / FK | 同一 spec 多条 = 价格变更历史 |
| price | decimal(10,2) | **拿货价** |
| supplier_id | FK | 本条报价来源（可与 Spec 默认供应商不同） |
| effective_at / created_by | | 生效时间、录入人 |

> 设计要点：**拿货价不直接放 Spec 上**，用历史表。一键计算取"生效时间 ≤ 计算日"的最新一条，保证重算结果可复现（呼应 NFR-08）。

**ShopProduct 店铺产品登记**

| 字段 | 类型 | 说明 |
|------|------|------|
| id / shop_id | PK / FK | |
| title_keyword | 文本 | 商品标题关键字 |
| link_id | 文本 | 抖店链接 ID |
| spec_id | FK | **必选**，来自成本表（选择器） |
| sale_price | decimal | 规格售价 |
| status | 枚举 | 启用/停用 |

**Batch 计算批次**

| 字段 | 类型 | 说明 |
|------|------|------|
| id / shop_id | PK / FK | |
| period | 文本 | 如"2026-08" |
| source_filename | 文本 | 原始 CSV 文件名 |
| stats | JSON | {总行数, 跳过无物流, 售后单数, 匹配数, 未匹配数, 实收, 成本, 利润} |
| created_by / created_at | | |
| status | 枚举 | 计算中/成功/失败 |

**OrderLine 计算明细行**

| 字段 | 类型 | 说明 |
|------|------|------|
| id / batch_id | PK / FK | |
| order_no | 文本 | 子订单编号 |
| raw_product | 文本 | 原始"选购商品"串 |
| title / spec_text | 文本 | 拆分后的标题/规格文本 |
| qty | int | 商品数量 |
| province | 文本 | |
| ship_fee_rule / ship_fee | 文本/decimal | 命中的附加规则与金额 |
| spec_id | FK, nullable | **匹配成功后回填**；未匹配为 null |
| unit_cost / line_cost | decimal | 单件成本（含附加）/ 行成本 |
| income | decimal | 商家收入金额 |
| matched | 枚举 | auto（自动）/ manual（人工）/ none（未匹配） |
| aftersale_status | 文本 | 仅展示 |

**MatchRule 匹配规则沉淀**

| 字段 | 说明 |
|------|------|
| shop_id + title_norm（标题规范化文本）+ spec_text → spec_id | 人工指定一次后沉淀；下次同文本自动命中（优先级高于模糊匹配） |

**附属实体**：AftersaleRecord（售后）、Invoice（发票：号码/金额/附件/提醒状态）、Reminder（提醒记录：类型/计划时间/已读）、AuditLog（操作日志）、RegionRule（附加规则：省份列表/金额/启停，预置两条可后台改）。

### 3.3 关键约束

- spec_code 全局唯一（DB 唯一索引）
- ShopProduct 同店铺内 (title_keyword, sale_price) 不允许重复登记
- 计算时价格快照：Batch 存当时命中的 cost_price 值（而非只存 FK），重算以批次为单位
- RegionRule 预置：
  - R1：海南/青海/内蒙古/宁夏/甘肃 → +4 元/件
  - R2：新疆/西藏 → +20 元/件

## 4. 关键页面原型

> 以下用文本线框描述结构，作为原型工具（Figma/Pencil）输入。

### 4.1 工作台

```
┌──────────────────────────────────────────────────────┐
│ 待办                    快捷入口                       │
│ ┌────────┐ ┌────────┐ ┌────────┐   [上传订单] [报价录入] │
│ │发票提醒 │ │未匹配   │ │报价待补│   [店铺登记] [看日报]   │
│ │ 3 条   │ │ 12 单  │ │ 2 项   │                      │
│ └────────┘ └────────┘ └────────┘                      │
│ 最近批次：誉恒 2026-08 · 成本 ¥12,345 · 利润 ¥6,789 →   │
└──────────────────────────────────────────────────────┘
```

- 待办卡按角色显示：客服看发票提醒，财务看未匹配，采购看待补录
- 卡片点击直达对应处理页

### 4.2 规格成本表（采购主数据核心页）

```
┌ 规格成本表          [新增规格] [导入XLSX] [下载模板] [导出]
│ 搜索: 编码/产品名/供应商        筛选: 供应商▾ 状态▾
├──────────────────────────────────────────────────────────
│ ☑ 编码     产品名称   规格    拿货价   供应商   更新时间  操作
│ SP000123  香葱椒盐月饼 60g×10枚  32.00  誉恒源   08-12   编辑 历史
│ SP000124  香葱椒盐月饼 60g×15枚  45.00  誉恒源   08-12   编辑 历史
│ …                                                        分页
└──────────────────────────────────────────────────────────
```

**新增/编辑规格（抽屉）**

```
产品名称 *  [________]        规格名 * [________]
默认供应商 * [选择 ▾]          本版拿货价 * [____] 元
产品图片    [上传]             备注 [________]
              [取消]  [保存并生成编码]
```

- 保存后自动生成 spec_code 并 toast 提示"编码 SP000125 已生成"
- 编辑价 = 新增一条 CostPrice 历史，不覆盖旧值
- **报价 OCR 入口**：抽屉顶部 [拍照/截图识别] → 上传图片 → 预填产品名/规格/价格 → 人工确认后保存（对应 Q4：识别结果必须人工确认）

**XLSX 导入弹窗**

```
上传成本表（固定模板）
① [拖入 .xlsx]     ② 表头自动校验: ✓ 店铺名称 ✓ 产品标题名 ✓ 规格售价 ✓ 拿货价
   预检: 共 86 行 · 新增 80 · 价格更新 5 · 异常 1（第 17 行规格售价为空）
                        [取消]  [确认导入]
```

- 表头不符：整表拒绝，列出缺失列
- 导入的行若无编码列，按"标题+规格"upsert 到 Spec（同名同规格则更新价格历史，否则新建并生成编码）

```
   └─────────────────────────────┘
③ 规格售价 *[69.90]        [取消] [保存]
```

### 4.4 订单上传与计算（财务主链路）

```
┌ 订单成本核算   店铺[誉恒▾]  期间[2026-08▾]
│
│ ┌─ 步骤条：① 上传 → ② 预检 → ③ 计算 → ④ 结果 ─┐
│
│ ① 拖入订单 CSV（文件名需含店铺名，如"誉恒8月份.csv"）
│
│ ② 预检报告
│    总行数 1521 · 可计算 1045 · 无物流跳过 476 · 售后单 58（计成本，仅展示）
│    预计未匹配 12 行（点击预览）
│                              [重新上传] [确认计算]
│
│ ③ 计算中…（进度条，≤30s / 万行）
│
│ ④ 结果页（Tab 切换）
│    [汇总] [成本明细] [未匹配 12] [导出]
└
```

**结果-汇总 Tab**

| 店铺名称 | 商家实收 | 发货单数 | 售后单数 | 采购成本 | 利润 |
|---|---|---|---|---|---|
| 誉恒 | ¥98,765.00 | 1045 | 58 | ¥45,678.00 | ¥53,087.00 |

**结果-未匹配 Tab（必须处理闭环）**

```
│ 订单号        选购商品(截断)        数量  省     操作
│ 6955570…    …60g*10枚             1   北京市  [指定编码] [忽略]
│ 批量: [按文本相同批量指定]  处理后 [重算受影响行]
```

- "指定编码"弹出与 4.3 相同的成本表选择器；确认后写 MatchRule 沉淀
- 忽略需填原因（审计留痕）
- 重算只重算该批次未匹配行，不整批重跑

### 4.7 系统管理

- **账号**：增删改、重置密码、启用/停用、角色
- **角色权限**：默认按需求文档权限表预置；管理员可勾选模块覆盖
- **附加成本规则**：省份多选 + 金额 + 启停（当前 +4/+20 两条预置）
- **操作日志**：人/时间/模块/动作/IP

## 5. 匹配算法细化（标题+售价 → 规格编码）

### 5.1 输入与预处理

对每个订单行：

1. 取 `选购商品`，按**最后一个 `-`** 拆为 `title` 与 `spec_text`
2. 规范化 `title_norm = title` 去空白/全半角统一/去促销符号（【】、`*` 等仅用于展示层，不进主键）
3. 取订单 `商家收入金额`/数量得单价（可选校验）、`省`

### 5.2 候选召回（按店铺限定）

只在该店铺的 ShopProduct（启用状态）中找候选：

```
candidates = { sp ∈ ShopProduct(sp.shop) 
             | sp.title_keyword 是 title 的子串
               或 title 是 sp.title_keyword 的子串 }
```

### 5.3 打分与排序

对每个候选计算：

| 优先级 | 规则 | 说明 |
|--------|------|------|
| 0（最高） | **MatchRule 精确命中**：规范化后 title 与沉淀规则文本相等 | 人工指定过的文本直接复用 |
| 1 | spec_text 与登记规格名**完全一致** 且 售价一致 | 双因子 |
| 2 | 标题关键字命中**长度最长** 且 售价一致 | 最长匹配 |
| 3 | 标题命中长度最长（售价不一致，仅弱命中） | 进入人工确认优先队列 |

- 售价比较：以订单行商品金额/数量 与 sale_price 差值 ≤ 0.01 视为一致
- 仅当唯一最高优先级候选存在 → **自动匹配（matched=auto）**
- 最高优先级并列多条，或最高为级别 3 → **不自动落库**，进未匹配清单（推荐候选可展示，需人工点确认）

### 5.4 未匹配与沉淀

```
人工指定 spec 后：
  写 MatchRule(shop, title_norm, spec_text) → spec_id
  回填该批次所有相同 (title_norm, spec_text) 的未匹配行
  重算受影响行成本 → 更新批次 stats
```

### 5.5 成本与汇总公式（定稿）

```
对每个订单行（快递信息有效）:
  hit = RegionRule 匹配省 → surcharge（无则 0）
  unit_cost = 命中报价的拿货价 + surcharge
  line_cost = unit_cost × qty

批次汇总（店铺 × 期间）:
  实收 = Σ income（全部行，含售后）
  发货单数 = 快递信息有效行数
  售后单数 = aftersale_status 非空行数（仅展示）
  采购成本 = Σ line_cost（含售后行；未匹配行不计入并单独披露）
  利润 = 实收 − 采购成本
  金额四舍五入 2 位；利润率 = 利润/实收
```

### 5.6 边界情况

| 场景 | 处理 |
|------|------|
| 一单多品（一个订单多个子行） | 每行独立匹配、独立算成本；明细按行展示（**Q11 设计口径**） |
| 同标题不同链接 ID | 多条 ShopProduct 共存，售价不同则靠售价区分 |
| 成本价变更后重算 | 取批次期间对应生效日的价格快照逻辑见 3.3；整批重算生成新版本批次 |
| 规格停用 | 已有登记不受影响；新登记不可选 |
| 省为空 | surcharge=0，正常计成本 |

## 7. 首版（MVP）范围建议
