# 02 数据模型设计

> 对应需求：核心数据实体、FR-PO-03（编码唯一）、NFR-08（可追溯）

## 1. ER 总览

```
供应商 1 ──── n 规格(Spec) 1 ──── n 成本报价(历史)
                    │ 1
                    ├──── n 店铺产品登记(ShopProduct) ── n 店铺(Shop)
                    │              └─（标题+售价 用于订单反查）
                    ├──── n 匹配规则沉淀(MatchRule)
                    │
订单批次(Batch)
      │
      └── n 订单行(OrderLine) ──→ 规格(Spec)（匹配成功后回填 spec_id）

发票 / 售后记录 / 提醒记录 / 操作日志（独立挂账号与供应商）
```

## 2. 实体定义

### Shop 店铺

| 字段 | 类型 | 说明 |
|------|------|------|
| id | PK | |
| name | 唯一 | 如"誉恒"；首版由 CSV 文件名前 2 字自动注册，管理员可改全名 |
| full_name / remark | 文本 | |

### Supplier 供应商

| 字段 | 类型 | 说明 |
|------|------|------|
| id / name | PK / 文本 | |
| wechat_group | 文本 | 对接微信群 |
| contact_name / contact_phone | 文本 | |
| products | 文本 | 供应产品描述 |

### Spec 规格（全系统主键载体）⭐

| 字段 | 类型 | 说明 |
|------|------|------|
| id | PK | |
| spec_code | **唯一** | 规格编码，系统自动生成：`SP + 6位序列`（如 SP000123），不可改 |
| product_name | 文本 | 产品名称 |
| spec_name | 文本 | 规格名（如"60g×10枚"） |
| supplier_id | FK | 默认供应商 |
| image | 附件 | 产品图片 |
| status | 枚举 | 启用/停用（停用后不可被新登记选择） |

### CostPrice 成本报价（Spec 价格历史）

| 字段 | 类型 | 说明 |
|------|------|------|
| id / spec_id | PK / FK | 同一 spec 多条 = 价格变更历史 |
| price | decimal(10,2) | 拿货价 |
| supplier_id | FK | 本条报价来源（可与默认供应商不同） |
| effective_at / created_by | | 生效时间、录入人 |

> 拿货价不直接放 Spec 上：一键计算取"生效时间 ≤ 计算日"的最新一条，保证重算可复现。

### ShopProduct 店铺产品登记

| 字段 | 类型 | 说明 |
|------|------|------|
| id / shop_id | PK / FK | |
| title_keyword | 文本 | 商品标题关键字 |
| link_id | 文本 | 抖店链接 ID |
| spec_id | FK | **必选**，来自成本表（选择器） |
| sale_price | decimal | 规格售价 |
| status | 枚举 | 启用/停用 |

### Batch 计算批次

| 字段 | 类型 | 说明 |
|------|------|------|
| id / shop_id | PK / FK | |
| period | 文本 | 如"2026-08" |
| source_filename | 文本 | 原始 CSV 文件名 |
| stats | JSON | {总行数, 跳过无物流, 售后单数, 匹配数, 未匹配数, 实收, 成本, 利润} |
| created_by / created_at | | |
| status | 枚举 | 计算中/成功/失败 |
| version | int | 重算生成新版本，旧版保留 |

### OrderLine 计算明细行

| 字段 | 类型 | 说明 |
|------|------|------|
| id / batch_id | PK / FK | |
| order_no | 文本 | 子订单编号 |
| raw_product | 文本 | 原始"选购商品"串 |
| title / spec_text | 文本 | 拆分后的标题/规格文本 |
| qty | int | 商品数量 |
| province | 文本 | |
| ship_fee / rule_id | decimal / FK | 命中的地区附加金额与规则 |
| spec_id | FK, nullable | 匹配成功后回填；未匹配为 null |
| unit_cost / line_cost | decimal | 单件成本（含附加）/ 行成本 |
| income | decimal | 商家收入金额 |
| matched | 枚举 | auto / manual / none |
| aftersale_status | 文本 | 仅展示 |

### MatchRule 匹配规则沉淀

| 字段 | 说明 |
|------|------|
| shop_id + title_norm + spec_text → spec_id | 人工指定一次后沉淀；下次同文本自动命中（优先级最高） |

### 附属实体

- **AftersaleRecord**：问题描述、处理结果、关联订单/客户
- **Invoice**：号码、金额、供应商、附件、提醒状态
- **Reminder**：类型、计划时间、已读、重试次数
- **RegionRule**：省份列表、金额、启停；预置 +4/+20 两条
- **AuditLog**：人、时间、模块、动作、IP

## 3. 关键约束

1. spec_code 全局唯一（DB 唯一索引）
2. ShopProduct 同店铺内 (title_keyword, sale_price) 不允许重复登记
3. 计算时价格快照：OrderLine 存当时命中的拿货价数值（非只存 FK），重算以批次为单位生成新版本
4. RegionRule 预置：
   - R1：海南/青海/内蒙古/宁夏/甘肃 → +4 元/件
   - R2：新疆/西藏 → +20 元/件
