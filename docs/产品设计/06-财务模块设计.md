# 06 财务模块设计

> 对应需求：FR-FIN-01 订单回传、FR-FIN-02 一键计算、FR-FIN-03 自动核算、FR-CALC 月度对账细则
> 使用角色：财务（写）｜老板（读）｜运营（成本只读）

## 1. 主链路总览（3 步出结果）

```
① 上传 → ② 预检 → ③ 计算 → ④ 结果（汇总/明细/未匹配） → ⑤ 导出
```

## 2. 订单上传（FR-FIN-01）

```
┌ 订单成本核算   店铺[誉恒▾]  期间[2026-08▾]
│ 拖入订单 CSV（文件名需含店铺名，如"誉恒8月份.csv"）
└
```

- 店铺识别：**文件名前 2 字**匹配店铺表；未命中则要求手动选店铺并提示
- CSV 关键列自动识别：`选购商品`、`快递信息`、`省`、`商品数量`、`商家收入金额`、`售后状态`、`子订单编号`
- 缺关键列 → 阻断并列出缺失列
- 待结算订单表（Q7 遗留）：二期，首版仅支持订单明细 CSV

## 3. 预检报告

```
总行数 1521 · 可计算 1045 · 无物流跳过 476 · 售后单 58（计成本，仅展示）
预计未匹配 12 行（点击预览）
                    [重新上传] [确认计算]
```

- **无物流过滤**：`快递信息` 为空或 `-` → 跳过，不计成本
- **售后口径（已确认）**：售后/退款行**仍计采购成本**；售后单数只做汇总展示列
- 预检未匹配预估：用当前启用的登记+MatchRule 做一次试匹配，提前暴露缺口

## 4. 计算引擎（FR-FIN-02 / FR-CALC）

单行公式（对每个有物流的订单行）：

```
拆分: 选购商品 → title + spec_text（按最后一个 "-"）
召回: 本店铺启用的 ShopProduct，标题互为子串
匹配: 见《07-匹配算法设计》→ spec_id
附加: RegionRule 命中省 → surcharge（+4 / +20 元/件，按件计）
成本: unit_cost = 拿货价(价格快照) + surcharge
      line_cost = unit_cost × qty
```

批次汇总：

```
实收     = Σ income（全部可计算行，含售后）
发货单数 = 有物流行数
售后单数 = aftersale_status 非空行数（仅展示）
采购成本 = Σ line_cost（含售后行；未匹配行不计入并单独披露）
利润     = 实收 − 采购成本
金额四舍五入 2 位
```

- 异步任务执行，进度条展示；1 万行 ≤ 30s（NFR-07）
- 计算落库为 **Batch**，行级落 OrderLine，价格存快照值

## 6. 未匹配处理（闭环，必须清零或显式忽略）

```
│ 订单号     选购商品(截断)     数量  省     推荐候选        操作
│ 6955570…  …60g*10枚          1   北京市 SP000123(90%)  [指定] [忽略]
│ 批量: [按文本相同批量指定]            [重算受影响行]
```

- 指定编码 = 打开成本表选择器 → 确认 → 写 MatchRule 沉淀 + 回填该批同文本行
- 忽略需填原因，审计留痕；被忽略行不计成本，汇总中单独披露忽略行数
- 重算只重算受影响行并更新批次 stats（整批重算见批次列表"重算"）
