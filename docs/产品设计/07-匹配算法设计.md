# 07 匹配算法设计

> 对应需求：FR-LINK-01、方案 A（标题+售价反查 → 落规格编码）
> 输入：订单行 `选购商品`、`商家收入金额`/数量；店铺启用的 ShopProduct 集合；MatchRule 沉淀表

## 1. 预处理

对每个订单行：

1. 取 `选购商品`，按**最后一个 `-`** 拆为 `title` 与 `spec_text`
2. 规范化：`title_norm = title` 去首尾空白、全半角统一、去装饰符号（【】、`*` 等仅展示层处理）
3. 计算单价：`price ≈ income / qty`（用于售价一致性判断，容差 ≤ 0.01）

## 2. 候选召回（限定本店铺）

```
candidates = { sp ∈ ShopProduct(sp.shop, status=启用)
             | sp.title_keyword ⊆ title  或  title ⊆ sp.title_keyword }
```

## 3. 打分排序（四级优先）

| 优先级 | 规则 | 说明 |
|--------|------|------|
| 0（最高） | **MatchRule 精确命中**：`title_norm` 与沉淀规则文本相等 | 人工指定过的文本直接复用 |
| 1 | spec_text 与登记规格名完全一致 **且** 售价一致 | 双因子 |
| 2 | 标题关键字命中**长度最长** 且 售价一致 | 最长匹配 |
| 3 | 标题命中长度最长（售价不一致，仅弱命中） | 只做推荐，不自动落库 |

## 4. 判定规则

- 存在**唯一**的最高优先级候选且优先级 ≤ 2 → 自动匹配（`matched=auto`），回填 spec_id
- 最高优先级并列多条，或最高仅为级别 3 → **不自动落库**，进未匹配清单；把 top-N 作为推荐候选展示（附命中分数）
- 完全无候选 → 未匹配清单，无推荐

## 5. 人工指定与沉淀

```
人工指定 spec 后：
  1. 写 MatchRule(shop_id, title_norm, spec_text) → spec_id
  2. 回填该批次所有相同 (title_norm, spec_text) 的未匹配行
  3. 重算受影响行成本 → 更新批次 stats
```

- 同一文本二次出现时优先级 0 直接命中，人工只做一次
- 人工改判已有 auto 匹配 → 以改判结果为准并更新 MatchRule（覆盖）

## 6. 成本公式（定稿）

```
unit_cost = 命中报价拿货价(快照) + RegionRule(省)
line_cost = unit_cost × qty
批次采购成本 = Σ line_cost（未匹配行除外，单独披露）
```

RegionRule 预置：

| 规则 | 省份 | 金额 |
|------|------|------|
| R1 | 海南、青海、内蒙古、宁夏、甘肃 | +4 元/件 |
| R2 | 新疆、西藏 | +20 元/件 |

规则存放于 RegionRule 表，系统管理页可增删改（金额、省份范围、启停），算法每次计算实时读取。

## 7. 边界情况

| 场景 | 处理 |
|------|------|
| 一单多品 | 每行独立匹配、独立算成本（Q11 已闭环：逐行归集） |
| 同标题不同链接 ID | 多条 ShopProduct 共存，售价不同靠价格区分 |
| 同标题同售价多登记 | 优先级并列 → 不自动匹配，进人工 |
| 成本价变更后重算 | 按批次期间取当时快照逻辑重算，生成新版本批次 |
| 规格停用 | 已有登记可继续命中；新登记不可选 |
| 省为空 | surcharge = 0，正常计成本 |
| qty 为 0/非数字 | 行级异常，跳过并入异常清单 |

## 8. 性能要点

- 召回用倒排：店铺内 `title_keyword → sp_id` 索引；规范化文本预计算
- 1 万行目标 ≤ 30s：批量入库后一次内存匹配（避免逐行查库），匹配完成后批量写 OrderLine
