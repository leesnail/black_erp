# 00 总体链路设计

> 对应需求：系统概述、核心数据联动逻辑（方案 A 主键）

## 1. 业务全景

系统主线：**货的成本从哪来 → 卖到哪 → 这一单赚多少**。五岗位在同一数据链路上协作：

```
┌─────────┐   供应商报价    ┌─────────┐   产品登记     ┌─────────┐
│  客服    │───────────────→│  采购    │──────────────→│  运营    │
│ 售后/发票 │  供应商信息     │ 成本+编码 │  （选编码）    │ 售价/链接 │
└─────────┘                 └────┬────┘               └────┬────┘
                                 │ 规格编码（全系统主键）      │
                                 └──────────┬───────────────┘
                                            ↓
                                    ┌─────────────┐   上传订单 CSV
                                    │    财务      │←────────────── 抖店后台导出
                                    │ 匹配→计算→汇总 │
                                    └──────┬──────┘
                                           ↓
                              ┌────────────────────────┐
                              │ 老板/管理员：经营驾驶舱   │
                              │ 日报·月度对账·利润总览    │
                              └────────────────────────┘
```

## 2. 四段式数据流

| 阶段 | 动作 | 产出 | 责任岗位 |
|------|------|------|----------|
| ① 建主数据 | 采购录供应商报价，系统生成**规格编码**；客服维护供应商对接信息 | 成本表（编码级） | 采购/客服 |
| ② 绑店铺 | 运营按店铺登记：标题关键字 + **必选编码** + 规格售价 + 链接 ID | 店铺产品登记表 | 运营 |
| ③ 算成本 | 财务上传订单 CSV → "标题+售价"反查编码 → 自动算成本/利润 | 明细 + 汇总 + 未匹配清单 | 财务 |
| ④ 看结果 | 日报自动推送；月度对账沉淀；驾驶舱全局查看 | 经营报表 | 老板/全员 |

## 3. 两条核心使用链路

**链路 A：日常成本核算（高频，财务）** — 价值核心，设计优先保证 3 步出结果：

```
导出订单 CSV → 上传（识别店铺名） → 预检报告（行数/无物流/疑似未匹配）
→ 确认计算 → 查看汇总/明细 → 处理未匹配（人工指定编码） → 重算 → 导出
```

**链路 B：主数据维护（低频，采购/运营）**：

```
采购：供应商管理 → 报价录入（手输/OCR） → 生成规格编码
运营：成本表选编码 → 登记店铺/标题/售价/链接ID
```

## 4. 设计原则

1. 编码不重、录入不烦：编码自动生成，运营侧只选不填
2. 财务侧闭环：任何"算不准"的订单必须有去处（未匹配清单），不得静默丢弃
3. 可追溯：批次不可变、价格有历史、重算生成新版本
4. 权限前置：无权限菜单不可见 + 接口拒绝
