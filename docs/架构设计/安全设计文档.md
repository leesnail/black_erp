# BLACK ERP 安全设计文档

> 版本：v1.0 · 日期：2026-10-20
> 依赖：《BLACK ERP 架构设计文档》《需求文档》
> 部署前提：内网 Windows 本地部署 + 内网穿透；远期可能迁云
> 范围：认证会话、授权、传输与穿透安全、数据安全、输入输出安全、审计备份、迁移清单

---

## 1. 威胁模型与安全目标

**信任边界**：内网部署机（高信任）→ 内网穿透公网入口（低信任）→ 浏览器端（不可信）。

| 资产 | 威胁 | 等级 | 主要对策 |
|------|------|:----:|----------|
| 成本价/利润数据 | 未授权员工越权查看 | 高 | 模块权限 + 接口鉴权 + 字段级过滤 |
| 账号 | 口令爆破、会话劫持 | 高 | 强口令策略、登录限速、Secure Cookie、穿透走 HTTPS |
| 上传文件 | 恶意文件（木马/超大/伪造扩展名） | 高 | 白名单、大小限制、随机化存储名、与代码目录隔离 |
| 数据库 | 注入、误删、单机故障 | 高 | ORM 参数化、最小权限账号、每日备份 |
| 内网穿透入口 | 公网暴露面被扫 | 高 | 只映射 80/443、HTTPS、可选 Basic Auth 前置门禁 |
| 操作 | 误操作无据可查 | 中 | AuditLog 全量关键动作 |
| CSV/XLSX 解析 | 解析器漏洞、公式注入 | 中 | 依赖固定版本、导出转义、不执行公式 |

**安全目标（按优先级）**：保密（成本利润仅授权可见）→ 完整（计算结果可追溯不可篡改）→ 可用（备份可恢复）。

## 2. 认证与会话（FR-Auth 落地）

| 项 | 设计 |
|----|------|
| 口令存储 | Argon2id（或 bcrypt cost≥12）；禁止 MD5/SHA 直存 |
| 口令策略 | ≥8 位，含字母+数字；首登强制改密；管理员重置为随机临时口令 |
| 登录限速 | 同账号 5 次失败锁 15 分钟（Redis 计数）；记录失败日志 |
| 会话 | 服务端 Session（Redis），Cookie：`HttpOnly + SameSite=Lax + Secure`（HTTPS/穿透下强制 Secure） |
| 会话时效 | 活跃续期 7 天，绝对上限 30 天；改密/停用账号立即吊销全部会话 |
| 二次确认 | 权限变更、删除批次、规则修改等高危操作要求重新输入密码 |
| 验证码 | 首期滑块/图形验证码可选开关；内网可关，开穿透后建议开 |

**小程序二期**：Session Cookie 不适用小程序，预留 **Token 双轨**——同一鉴权层同时支持 Cookie（PC）与 `Authorization: Bearer`（小程序），Token 存 Redis 同一套会话表。

## 3. 授权（双层 + 字段级）

```
第一层：前端菜单/按钮按权限码渲染（体验，不是安全边界）
第二层：后端每个 API Depends(perm("模块.动作"))，未授权 403
第三层：敏感字段序列化过滤（客服接口不返回拿货价/利润）
```

- 权限码粒度：`模块.动作`（如 `calc.write`、`master.read`、`admin.account`），与角色-页面矩阵一一对应
- 水平越权防护：所有列表/详情接口强制作用域过滤（店铺、批次归属），禁止信任前端传参的 shop_id
- 默认拒绝：未配置权限码的接口启动时自检报警（防止新接口漏配鉴权）

## 4. 传输与内网穿透安全

### 4.1 网络暴露面

| 端口 | 内网 | 穿透公网 | 说明 |
|------|:----:|:--------:|------|
| 80/443（Nginx） | ✓ | ✓（仅 443） | 唯一业务入口 |
| 8000（app） | ✗ | ✗ | 仅容器网络 |
| 3306/6379 | ✗ | ✗ | **绝对不对内网/公网开放** |

### 4.2 穿透方案

| 方案 | 做法 | 建议 |
|------|------|------|
| 自建 frps（推荐） | 最小 VPS 跑 frps + 域名 + Let's Encrypt；部署机 frpc 只反代 80 | 流量路径可控，证书自己管 |
| 托管穿透（cpolar/花生壳） | 开箱即用 | 快速验证用；确认服务商不留存日志策略后再放正式数据 |

### 4.3 穿透加固清单

1. 穿透域名启用 HTTPS（TLS1.2+），HTTP 强制跳转
2. Nginx 可选 **Basic Auth 前置门禁**（多一道门，防穿透域名被扫后直打登录页爆破）
3. 登录接口 `/api/auth/login` 公网路径下强制验证码 + 限速
4. 穿透入口加 IP 白名单（若远程成员 IP 固定）
5. 关闭服务器指纹：Nginx `server_tokens off`；API 错误不返回堆栈
6. frpc/token 定期轮换；穿透配置不进 git

### 4.4 内网同样要鉴权

内网≠安全：内网也走完整登录+权限；禁止"内网免登"后门。

## 5. 数据安全

| 项 | 设计 |
|----|------|
| 数据库账号 | 应用连接用最小权限账号（非 root）；root 只在运维 |
| SQL 注入 | 全部 ORM 参数化；禁止字符串拼 SQL；动态排序字段白名单 |
| 备份 | Windows 任务计划程序：mysqldump 每日全备 + uploads robocopy，保留 30 天；备份目录与数据目录分离 |
| 恢复演练 | 每季度一次恢复演练（备份→临时库校验行数），记录结果 |
| 金额字段 | DECIMAL，无 float；计算批次不可变，防事后篡改 |
| PII | 收件人手机号列表页脱敏（138****1234），详情按权限可见；导出文件含 PII 的操作入审计 |
| 密钥配置 | `.env` 不进 git；穿透 token、数据库口令只在部署机本地文件；文件权限收紧 |

## 6. 输入与输出安全

### 6.1 上传文件（CSV/XLSX/图片/发票附件）

- 扩展名 + **MIME 魔数**双白名单：`.csv/.xlsx/.jpg/.png/.pdf`；拒绝 `.xls`（宏风险）、可执行文件
- 大小限制：Nginx `client_max_body_size 50m` + 应用层二次校验
- 存储：随机 UUID 文件名（不保留原始名做路径），存 `uploads/` 数据卷，**与应用代码目录隔离**；Nginx 对 uploads 目录禁止执行权限、禁止直接按路径猜访（下载走带权限的接口）
- XLSX：openpyxl 只读解析，不解析公式结果为信任值；导出时对文本单元格做转义防公式注入（`=`/`+`/`-`/`@` 开头加前缀）

### 6.2 XSS / CSRF / 点击劫持

- 前端 Vue 模板默认转义，禁止 `v-html` 渲染用户输入（发票备注等一律纯文本）
- CSRF：Session Cookie + 自定义 Header Token（`X-CSRF-Token`）双提交；所有写操作校验
- `X-Frame-Options: DENY`、`X-Content-Type-Options: nosniff`、CSP 收敛（首期 `default-src 'self'`）

### 6.3 业务输入校验

- Pydantic 全接口入参校验；金额/数量类型与范围约束
- 重复提交：关键按钮幂等（Batch 创建带 token，重复点击不产生重复批次）

## 7. 审计与监控

**AuditLog 必记动作**：登录/登录失败、权限变更、账号停用/重置、成本价修改、XLSX 导入、批次计算/重算、人工匹配/忽略、规则修改、数据导出。

字段：时间、人、IP、模块、动作、对象 id、变更摘要（前后值截断）。日志只读、不可删、不可改；保留 ≥ 1 年。

**告警（首期轻量）**：Batch running 超 10 分钟、登录失败风暴、备份任务失败——写入工作台管理员待办（不做短信/邮件通道，二期接 NotifyProvider）。

---

## 8. 依赖与漏洞管理

- `requirements.txt`/lock 锁版本；季度 `pip audit` / `npm audit`，高危 7 天内升级
- 基础镜像用官方 slim，定期重建打补丁
- 禁止引入无维护的解析类依赖；pandas/openpyxl 固定兼容版本
